# 디자인 화면 → Figma 내보내기

## 지시사항 (사용자 원문)

1. 디자인된 화면을 **링크의 Figma 파일**로 보낼 것
2. **컴포넌트 적용된 상태**로 내보낼 것
3. **컴포넌트는 별도 이미지에 생성**할 것

## 해석 및 작업 방식

- **대상 파일**: 사용자가 준 Figma 링크의 파일에 넣는다. 링크가 없으면 새 파일을 만들지 말고 먼저 링크를 묻는다.
- **컴포넌트 원본 위치**: "별도 이미지"는 화면 디자인과 분리된 **별도 페이지(예: `Components`)**로 해석한다. 컴포넌트 원본(main component)은 모두 그 페이지에 만든다.
- **화면 페이지**: 화면 디자인은 따로 둔 페이지(예: `Design`)에 만들고, 반복되는 요소는 직접 그리지 않고 **컴포넌트 인스턴스**로 배치한다.
- 컴포넌트로 만들 요소는 화면에 실제로 있는 것만 대상으로 한다. 예: 로고, Nav 메뉴 항목, 햄버거 버튼, 슬라이드 인디케이터, 버튼, 아이콘. 화면에 없는 요소를 새로 만들지 않는다 (CLAUDE.md 작업 원칙).
- 색·폰트는 `index.html`과 CLAUDE.md "현재 구성"의 값을 그대로 쓴다. 가능하면 색은 Figma 변수/스타일로 등록한다.
- 이미지(hero 사진, 제품 이미지)는 `index.html`의 data URI 이미지를 추출해 업로드해서 쓴다.

## 절차

1. `git pull`로 최신 `index.html`을 받는다.
2. Figma MCP를 쓰기 전에 Figma 스킬을 먼저 읽는다: `figma-use`(use_figma 호출 전 필수), `figma-generate-design`. 플러그인 스킬이 없으면 Figma MCP 리소스 `skill://figma/figma-use/SKILL.md`, `skill://figma/figma-generate-design/SKILL.md`를 읽는다.
3. 링크에서 fileKey를 확인하고 `get_metadata`로 기존 페이지 구성을 본다. 기존 내용은 지우거나 덮어쓰지 않는다. 필요하면 사용자에게 묻는다.
4. `Components` 페이지에 컴포넌트 원본을 만든다 (상태가 있으면 variant로 묶는다. 예: 인디케이터 active/inactive).
5. `Design` 페이지에 화면(데스크톱 기준, 필요 시 모바일)을 만들고 컴포넌트는 인스턴스로 배치한다.
6. `get_screenshot`으로 결과를 확인해 웹 화면과 비교하고 차이를 고친다.
7. 사용자에게 Figma 링크와 만든 컴포넌트 목록, 해석한 부분(특히 "별도 이미지" → 별도 페이지)을 한국어로 알린다.
